MergeScope 功能与测试知识库

基线：本地代码 v1.5.0。整理日期：2026-11-16（Asia/Shanghai）。用途：需求理解、变更影响分析、测试设计与回归验证。

本文件描述当前工作区实现，不等于远端版本、已安装扩展或正式发布状态。自动化通过、模拟平台检查、真实平台执行、实际邮件送达及业务验收必须分别记录。现行流程仅使用 AI，不再使用模块配置或路径命中规则给新报告定级。

01 产品边界与核心链路

分类：总览。优先级：P0。知识编号：MS-OVERVIEW。

Chrome / Edge Manifest V3；支持 GitHub.com、GitLab.com、HTTPS 自建 GitLab；不支持自建 GitHub Enterprise。

当前链路：保存订阅 → 读取合并 PR/MR 或默认分支提交 → 持久化任务 → 读取真实差异及知识索引/正文 → AI 分析 → 校验结构化风险结果 → 保存报告 → 可选正常邮件 → 阅读、容量归档与高风险定位。

手动支持真实 commit、PR/MR 和仓库首页；首页解析默认分支最新提交，其他分支需指定目标 commit。

必须配置并启用 AI 才能生成新报告。未启用、请求失败、仅推理或空正文时明确报错，不回退规则报告，不用失败请求覆盖已有报告；自动任务沿用队列重试。

分析不执行测试、不修改目标仓库。浏览器关闭、系统休眠时不承诺运行；约一分钟是调度间隔，不是送达 SLA。

回归操作：关闭 AI 后提交分析，观察明确错误且不保存伪成功报告；模拟 AI 故障后检查原报告仍在、任务保留且重试预算正确。

来源：README.md；extension/manifest.json；extension/background.js。

验证入口：tests/knowledge-background.test.js；tests/commit-scan.test.js；scripts/browser-smoke.mjs。

02 订阅、检查点与任务队列

分类：后台流程。优先级：P0。知识编号：MS-QUEUE。

最多订阅 20 个仓库。PR/MR 从首次保存时间跟踪；默认分支首次只分析最新提交并建立 SHA 检查点，不补齐全部历史。

后续按旧 SHA 找出新提交，较早提交先排队。实时分支引用固定扫描快照并绕过缓存，队列先于检查点持久化，不能只更新游标而丢任务。

单仓库历史扫描最多 1000 条；超限或引用/历史不一致需报错，不能当无更新。强推或默认分支变更导致检查点失效时提示并从最新位置跟踪。

每轮最多处理 2 个任务。累计失败 5 次停止自动重试；“立即重试”可跳过退避手动尝试一次，不重置额度。暂停仓库不能立即重试。

编辑订阅不重置检查时间；移除订阅清除相关等待任务，历史报告保留。发现提交不代表报告生成成功。

“等待分析”点击打开侧边栏，显示仓库、标题、失败次数、错误和重试时间；支持关闭、Escape、点击遮罩外侧及窄屏显示。

回归操作：首次订阅、一次 push 多提交、重复检查、报告丢失补建、重启恢复、5 次失败、手动重试和暂停分别验证，观察完整 SHA、任务数量、尝试次数和去重结果。

来源：extension/background.js；extension/provider.js；extension/core.js；extension/dashboard.js。

验证入口：tests/commit-scan.test.js；tests/queue-retry.test.js；tests/provider.test.js；scripts/queue-retry-smoke.mjs。

03 平台接口与仓库令牌隔离

分类：平台与权限。优先级：P0。知识编号：MS-PROVIDER。

GitHub 令牌按仓库保存，专用令牌优先；未配置时兼容旧站点令牌，显式清除同时阻止该仓库旧令牌回退，不影响其他仓库。GitLab 按站点保存。

GitHub 建议目标仓库 Contents 与 Pull requests 只读权限；GitLab 使用 read_api。已保存不代表已验证权限。

“测试访问”分别检查仓库信息、PR/MR 列表和默认分支提交。错误注明接口及是否携带令牌，不展示令牌或平台原始错误正文。

文件分页保留重命名前后路径、删除状态、二进制、缺失或截断差异。目标仓库知识按目标 ref 读取；知识来源可指定自己的版本参数，不可把两个仓库的版本混为一谈。

GitLab MR /diffs 遇 404/405/500/502/503/504 时尝试一次 /changes；401/403/429 不走兼容。备用失败保留错误，备用完整结果不能与此前分页重复拼接。

回归操作：分别保存 A/B 仓库令牌，验证留空、替换、清除及旧值回退；检查手动分析、自动扫描和知识来源请求分别使用对应令牌。

来源：extension/provider.js；extension/repo-token.js；extension/background.js。

验证入口：tests/provider.test.js；tests/repo-token.test.js；scripts/repo-token-smoke.mjs。

04 仓库知识来源与版本追溯

分类：分析能力。优先级：P0。知识编号：MS-KNOWLEDGE。

每仓库最多 8 个来源。Git 来源每项填写 1–10 个相对文档路径，可使用分支、标签或 SHA；需要不可变快照时显式填写 SHA，分支名并非永久固定版本。

本地文件夹支持 MD/MDX/TXT/JSON/YAML/CSV/RST/ADOC；每来源最多 50 份文本、每份最多 150000 字符，导入文件还需不超过 150000 字节，仓库本地文本合计最多 1000000 字节。跳过 .git、node_modules、锁文件及不支持格式。

网页来源单页最多 1000000 字节，提取文字保留前 150000 字符并提示截取；不携带登录 Cookie、不运行脚本、不跟随重定向。网页链接不会递归抓取，动态或登录正文需另行转存文本。

HTML 文件不参与本地知识导入。本目录 mergescope-knowledge.md 用于导入，两个 HTML 文件用于离线查阅；如用网页来源，需另行提供最终 HTTPS 地址。

已移除模块配置入口；分析不读取/合并 .merge-impact.json，不使用 paths/dependsOn/critical 自动生成新报告风险或回归明细。仓库中的旧配置和旧工具属于历史资源，不能当作当前生效规则。

预览不等于保存。编辑在原条目更新；未应用的编辑不能直接保存，带草稿退出或 Escape 需确认。来源正文是数据，不执行其中的指令。

回归操作：新增、原位编辑、取消、未保存退出、移除、权限撤销、超限和读取失败分别验证；观察草稿、已保存值、仓库隔离和具体警告。

来源：extension/knowledge-sources.js；extension/provider.js；extension/dashboard.js。

验证入口：tests/knowledge-sources.test.js；tests/knowledge-background.test.js；scripts/browser-smoke.mjs。

05 AI 报告结构、业务字段与导出

分类：分析能力。优先级：P0。知识编号：MS-ANALYSIS。

正文固定四部分：一、实际业务变化；二、影响范围和风险；三、测试重点；四、待确认事项。缺少资料也保留对应标题说明限制，不编造内容。

“实际业务变化”使用业务模块、角色、业务对象、修改前→修改后、状态/断言变化字段。模块采用需求/手册中的业务名称，缺少依据时待确认；角色不能推测；业务对象是模板、发布申请等实体，变量/ID/名称/版本仅用于定位，按钮与列表行属于操作位置或界面元素。

页面、菜单、按钮、接口的具体入口放在变化说明或测试步骤。仅测试脚本变化不能直接认定产品业务规则改变。

“影响范围和风险”使用易读小标题：本次代码改了什么；结合需求文档需要核对的内容；可能出现的问题及检查重点；目前缺少哪些判断依据。

历史预览兼容替换第一部分旧“入口、角色、对象”表头，保留原单元格内容；重新分析才会按新定义生成值。历史四处旧风险说明标题支持预览、Markdown 导出和后续邮件文字替换，代码块不替换。

正文后提供读取文档范围、变更文件、知识文档摘录。可展开完整 diff 文件清单与知识文档清单；未知完整性与缺失/不完整差异分开显示。

Markdown 导出记录报告风险及说明、快照、正文和资料范围；邮件调用同一导出逻辑。预览格式化不代表已执行测试或完成验收。

回归操作：比较四部分顺序及附录顺序；检查旧新表头、普通正文和代码块；对照页面/导出/邮件中的风险标签及标题，不改写原始业务说明。

来源：extension/ai-context.js；extension/core.js；extension/report-labels.js；extension/markdown-preview.js；extension/dashboard.js。

验证入口：tests/report-analysis.test.js；scripts/evidence-metrics-smoke.mjs；scripts/browser-smoke.mjs。

06 AI 模型设置、上下文与输出状态

分类：分析能力。优先级：P0。知识编号：MS-AI。

AI 初始关闭；启用后将标题、描述、差异、知识文档与读取范围发送到指定 HTTPS Chat Completions 兼容服务。未启用或调用失败时不生成规则兜底报告。

同一接口与模型组合更新原配置，不同组合保存多项；Key 和连接测试结果独立。新模型不继承其他 Key，修改/清除 Key 后旧测试结果失效。

最多发送前 80 个文件、每个 diff 最多 6000 字符、差异总预算 56000 字符；文档每份最多约 8000 字符。序列化用户输入预算 108000 字符附近，保留有效 JSON，limits 与系统提示另有开销，不能当作模型总 token 限额。

按提交标题、描述的中文词/双字片段和文件路径词排序资料；长正文选导言和相关片段，未命中时取前 8000 字符。它是关键词选取，不是完整语义检索，不能保证读到全部相关条款。

四部分正文要求不超过 2500 字、最多 8 条测试重点摘要。分析输出上限 8192 token，连接测试 512 token，非流式 JSON；单次分析请求超时 25 秒。

仅推理、空正文、拒绝、错误对象、HTML/流式/非法 JSON 分别报错；截断但有最终正文时保留部分正文并标未完成，不能据此保存确定高风险；连接测试拒绝截断结果。

不自动续写单次回答。自动分析失败由任务队列重试，不能混淆为模型自动续写。历史无截断字段不代表已验证内容完整。

回归操作：模型 Key 隔离、停用、超时、分段正文、仅推理、部分输出、长文档后部定位和预算省略分别验证；检查实际发送范围与保存元数据。

来源：extension/background.js；extension/ai-response.js；extension/ai-context.js；extension/risk-policy.js。

验证入口：tests/ai-models.test.js；tests/ai-response.test.js；tests/report-analysis.test.js；scripts/browser-smoke.mjs。

07 邮件服务与发送状态

分类：邮件与归档。优先级：P0。知识编号：MS-MAIL。

扩展通过本机 Node.js 邮件服务发送；原生桥接可启动/复用后台服务，健康检查成功后保存连接密钥。本机服务密钥与 SMTP 授权码不同，界面不回显秘密。

自动普通邮件由开关控制；手动补发支持重试，失败保留报告。容量归档的发送不受普通自动发送开关控制，不能把开关关闭理解为禁止所有归档发信。

收件人按逗号、分号、空白拆分去重，启用时支持 1–20 个有效收件人。密钥禁止空白、换行、中文说明或全角字符。

全部收件人被 SMTP 接受才记 sent，部分拒绝记 partial。SMTP 接受不等于到达收件箱；结果未确认时重试可能重复投递。

错误分类与脱敏涵盖认证、DNS、连接、TLS、地址和内容拒绝。系统 DNS 解析动态地址，保留原域名进行 TLS SNI/证书校验。

普通高风险邮件主题增加【高风险】；高风险归档主题以【高风险报告归档-日期时间-仓库名字】开头，普通归档为【报告归档-日期时间-仓库名字】。日期时间取原报告 createdAt，按北京时间格式化，发送状态记录实际发送时间。

回归操作：错误密钥、认证拒绝、网络超时、部分拒绝、重复补发、错误脱敏、草稿不影响已保存值，以及高风险/普通归档主题分别检查。

来源：extension/mail.js；extension/background.js；scripts/mail-service.mjs；scripts/mail-native-host.mjs；scripts/install-mail-native.mjs。

验证入口：tests/mail.test.js；tests/mail-native.test.js；tests/report-risk.test.js；scripts/high-risk-smoke.mjs。

08 报告容量、归档与回收站

分类：邮件与归档。优先级：P0。知识编号：MS-RETENTION。

当前合并分析记录仍保留最新 50 份，按生成时间淘汰最早记录。高风险统计不受此上限约束，但未归档容量及存储失败仍可能阻止新分析。

已归档仅保留摘要，不保留完整正文。已记录的高/中/低/待确认等级保留风险结果、仓库与定位信息；高风险另保留 highRisk 标记。无风险信息的旧摘要可能仅有标题、时间、链接和邮件状态。

普通报告若邮件已发送可直接归档；高风险即使发过普通邮件，移出时仍需单独成功发送一次 archive=true 的归档邮件，不能把普通 sent 当成归档成功。

移出前最多累计尝试 5 次，发送前持久化次数；失败五次则完整存入未归档，保留风险、AI 正文、文件和错误。重启不能重置额度。

未归档最多 10 份，支持查看、导出、补发归档及确认删除。满额时若下一份仍需要归档发送则阻塞；已满足归档条件的记录仍可腾位。

归档写入失败应回滚移出操作并保留完整报告。手动删除未归档报告后不再纳入高风险统计；没有供定位的记录不能虚增统计。

回归操作：49/50/51 与未归档 9/10 边界、普通 sent 与高风险 archive sent、五次失败、后台中断、存储失败、补发归档、风险标记持久化分别验证。

来源：extension/report-retention.js；extension/report-risk.js；extension/background.js；extension/mail.js。

验证入口：tests/report-retention.test.js；tests/report-risk.test.js；tests/mail.test.js；scripts/high-risk-smoke.mjs。

09 工作台、路由、阅读与风险标签

分类：界面与数据。优先级：P1。知识编号：MS-UI。

五个视图：分析工作台、仓库订阅、AI 分析设置、邮箱报告设置、分析报告回收站；支持直达、刷新、前进后退和菜单高亮，切换保留表单草稿。

当前统计卡片为订阅仓库、已生成报告、高风险变更、等待分析。“AI 正文完整”已被替换，不能用旧名称解释现在的高风险统计。

报告默认筛选全部，支持按仓库及单次分析记录筛选。桌面标题/元信息固定、正文独立滚动，同报告刷新保留位置，切换回顶部。

合并记录、详情及回收站统一显示高风险红标、中风险黄标、低风险绿标、风险待确认灰标；完全没有可靠等级时显示“未记录等级”。颜色与文字同时传达含义，不能只靠颜色。

旧规则数字 1/2/3 可显示低/中/高，并注明历史规则来源；仅 AI 模式不从旧数字猜测。没有等级不能默认算低，旧摘要丢失字段无法自动恢复。

新报告与重新分析默认为未读；活动工作台真正显示详情后才标已读，后台页/设置页/弹窗不标读。无字段旧报告初始化已读；0 隐藏角标，归档不计未读。

用 ID 与 createdAt 区分新旧报告实例，过期标读请求不能覆盖新报告。高风险跳转定位也用报告标识和生成时间，避免同标题误跳。

回归操作：各等级在三个位置显示、刷新和归档后保留；并检查五页路由、筛选、正文滚动、未读幂等、重分析竞态、键盘和窄屏。

10 数据安全与验证边界

分类：界面与数据。优先级：P0。知识编号：MS-SAFETY。

凭据在本机 chrome.storage.local 保存，不做账号同步，但不是系统凭据保险库；卸载会删除本地数据，清除令牌/Key 需明确操作。

仓库文档、diff、标题、AI 正文、网页和错误消息均是不可信数据。资料只供分析，不执行其中脚本、命令或指令，不把报告当作测试执行结果。

AI 正文通过本地打包的 Marked + DOMPurify 渲染，清理脚本、事件属性、表单、危险链接，图片不自动加载。代码块保留字面内容，安全 HTTP(S)/mailto 链接在新标签页打开。

标题、列表名、侧边栏条目等采用文本写入；报告表格不应通过 id/name 覆盖页面控件。下载和邮件不得包含令牌、Cookie、API Key 或 SMTP 授权码。

风险严重程度、依据充分程度、模型输出完成、SMTP 接受、实际送达、测试通过与发布验收是不同结论，不能互相替代。

回归操作：恶意 Markdown/HTML、事件属性、危险协议、外部图片、代码中的脚本字面量、跨仓库资料混入、凭据回显、存储失败分别验证。

来源：extension/markdown-preview.js；extension/dashboard.js；extension/background.js；extension/knowledge-sources.js；extension/mail.js。

验证入口：tests/repo-token.test.js；tests/knowledge-sources.test.js；tests/mail.test.js；scripts/evidence-metrics-smoke.mjs；scripts/browser-smoke.mjs。

11 变更影响分析与回归使用方法

分类：使用与维护。优先级：P1。知识编号：MS-WORKFLOW。

13 报告风险判定、高风险统计与归档定位

分类：风险与归档。优先级：P0。知识编号：MS-RISK。

当前风险口径见 extension/risk-policy.js，版本为 2026-11-16。分别分析产品业务、自动化测试、配置部署风险；目录/敏感词/文件数/删除重命名本身不直接定级。

高风险：具体代码变化与可信链路可能造成权限绕过、敏感数据泄露、不可逆数据损坏、关键账务错误或核心流程大范围阻断；需说明触发条件、严重后果、影响范围和代码依据。

中风险：具体变化可能引起功能回归、局部失败、兼容或可恢复的数据/状态不一致；低风险：已有上下文足以支持影响有限，不是默认值或零风险保证。

关键依据缺失时为待确认；潜在后果严重但链路不明时说明“潜在高影响，现有资料不足，待确认”，不能强行高/低。测试脚本变更不等于产品变化，但测试代码的真实写入/删除也不能自动降级。

AI 在正文前返回 MERGESCOPE_RISK 结构化注释，保存 level、reason、trigger、consequence、evidenceRefs、source、policyVersion。标记从展示正文中移除，不作为第五章节。

程序校验 high/medium/low/unknown 枚举与非空说明；高风险额外要求触发条件、后果，以及至少一个实际发送且 patch 非空、未标缺失的文件路径。高风险字段无效、缺少标记或输出截断时转为 unknown，不能从 P0 或“高风险”字样猜测。

上述校验只验证格式、字段和文件引用存在，不自动证明语义/影响链路成立；中低等级也不是经过业务复核的结论。P0/P1/P2 始终是测试场景优先级。

高风险卡片合并当前记录、回收站已归档和未归档，按 ID（缺失则原链接）与 createdAt 去重，按时间倒序，无50份统计截断；已删除记录不计。

侧边栏第一个Tab“高风险变更报告”展示标题、位置、来源与说明；点击自动关闭，当前报告切回全部筛选选中高亮，回收站报告切到对应分类并滚动高亮。第二个Tab“风险判定规则”共享当前口径，支持键盘左右/Home/End与Escape。

回归操作：准备当前、已归档、未归档高风险及中低/未知对照；统计超过50份、重复去重、同标题不同实例定位、移出后计数不丢失、刷新持久化。模拟归档失败五次观察完整报告保留，成功观察高风险前缀和摘要。

15 从知识索引继续读取正文与范围说明

分类：知识读取。优先级：P0。知识编号：MS-INDEX-READ。

Git 知识来源和目标仓库默认 README/架构文档支持总索引 → 文档索引 → 正文分片。沿同一仓库、同一 ref 参数读取，不自动访问外部站点；知识仓库令牌不能借用分析仓库的其他专用令牌。

支持 Markdown 内联/引用式链接、中文百分号编码、相对路径、锚点。跳过图片、Word/PDF原件、返回索引导航、越出仓库根路径、危险路径和 .merge-impact.json；重复与循环链接去重。

每次索引读取最多尝试50个文件、最多跟进3层链接、已载入文字合计1000000字节；失败尝试也占文件数。达到限制或失效链接明确提示，不能把上限后的正文算作已读。

分析时根据提交标题关键词优先跟进相关链接，预览无具体提交时按索引次序展开。相关性排序不保证业务关联成立，也不保证限额内覆盖所有需求。

Git 单文件平台读取仍限制150000字节；正文不再先截成16000字符，AI从已加载正文再选最多约8000字符的全文/片段。加载完整与AI收到完整是不同状态。

本地快照仅能读取已导入文件，缺少链接正文提示重新导入完整文件夹，不擅自读取磁盘。网页来源仍只读配置的单个页面，不沿链接递归。

范围记录包括文档路径、kind（正文/索引及链接文档/文档）、linkedFrom、原始和已加载字数、实际发送字数、selection。报告摘录仅保留前1800字符，不等于AI只读1800字符；长文档AI选取也不等于已读全文。

REF定位来源文档，正文_001等定位分片，B编号为转换内容块，不自动等于正式需求/用例编号。引用块存在不保证AI解释正确，空块、图片、相邻块和同名不同版本需回原文核对。

回归操作：中文路径、多层索引、重复/循环、外链、越界、404、三种读取上限、本地缺正文、超过16000字符尾部匹配分别验证；观察实际payload含正文、来源链与截取提示。

来源：extension/knowledge-links.js；extension/knowledge-sources.js；extension/provider.js；extension/ai-context.js。

验证入口：tests/knowledge-links.test.js；tests/knowledge-sources.test.js；tests/report-analysis.test.js；scripts/browser-smoke.mjs。
